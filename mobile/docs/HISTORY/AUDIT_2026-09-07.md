## What was audited, and how

The owner asked for a full audit of `mobile/` towards production readiness: bugs, UI/UX
polish, route tracing, module gating, completeness. This pass ran the day after the
2026-09-05/06 audit, so it deliberately did not re-report anything that audit fixed
(`CHANGELOG.md`, `[Unreleased]`).

Evidence tiers, honestly stated:

- **Source evidence.** Every finding below was verified against the current code by a
  second read before it was fixed; every fix has a Jest test that was observed failing
  before and passing after, or extends a test that already exercised the path.
- **Mechanical checks.** Type-check, lint, the 416-suite Jest run, the drift/parity/API
  ledger, the untranslated-phrase ceiling, release configuration, network security policy,
  production dependency audit, Play asset validation and the startup budget all passed on
  the pre-audit tree and again after the fixes (a bundle was NOT rebuilt, so the budget
  figure is the previous build's).
- 🔴 **No device evidence.** Nothing here was walked on an emulator or a phone. Layout and
  gesture findings from the auditors are recorded as such and were fixed only where the
  code made the fault unambiguous.

## Cross-cutting finding: module gating

The React app wraps about 150 routes in `<FeatureGate>`; the native app gated its menus and
five authoring screens. A deep link, a push notification, a shared URL or a screen pushed
from another screen reached every other module regardless of the community's switches.

Fixed: `lib/navigation/routeRequirements.ts` is one table of screen → required feature or
module, read by `components/withRouteGate.tsx` (wraps every screen's default export),
`app/(tabs)/_layout.tsx` (hides a tab whose module is off) and the deep-link store. Unknown
configuration (cold start, offline, tests) allows. `app/routeGating.test.ts` fails when a
new screen has no recorded decision, and `routeRequirements.test.ts` proves the deep-link
store and the screen gate agree for every gated route. Home is deliberately ungated (it is
the anchor every redirect lands on) and gates its own feed section.

Still a courtesy, not a boundary: the API does not enforce `courses` or `podcasts`
(recorded 2026-09-06, still open, owner decision).

## The marketplace, audited separately

The first marketplace auditor was killed by the account's session usage limit with nothing
written. A second, run alone, read the module in full. It found no crash or data-loss class
and confirmed the order idempotency key and its server-side fingerprint replay are sound —
but six P1 findings on the money path, all fixed here:

- **Checkout never showed a total.** The item price was at the top of the screen, each
  delivery option carried its own price, and an applied coupon showed no figure at all
  because the server's discount amount was discarded. A card buyer first saw the real charge
  in the Stripe sheet; a time-credit buyer never saw one.
- **A time-credit or free purchase committed on one tap.** The server debits the wallet as
  the order is created, so the tap on "Buy now" *was* the purchase.
- **A payment that went through could be reported as failed.** If the app's confirm call
  failed after Stripe had charged the card, the member was told "Payment failed" and could
  pay again.
- **Cancelling the payment sheet gave the wrong instruction** and stranded an unpaid order
  with no route to it; the checkout key was also never cleared after a completed order.
- **"Free" was shown for any empty price**, so "contact seller" and time-credit-only
  listings were labelled Free on every list.
- **"Confirm delivery" released the seller's money on one untitled tap**, beside "Dispute".

Plus: offer actions had no busy state and no confirmation; orders and offers had no
pull-to-refresh although payment hand-offs return to them; coupon minimum-order and max-uses
were parsed with `Number()` on a decimal-pad field; the public coupon list showed "No
coupons" on a failed request; the pickup code was text the seller had to type while their own
tools tab offers a scanner; and the 3-D Secure return URL had no screen behind it.

## Findings fixed in this pass

Identifiers are `report/finding` as the auditors numbered them.

**Money and credits**
- B/F-02 — a time-credit transfer committed on one tap, and a deep link could name an
  unverified recipient. Now: confirmation dialog naming recipient and amount; the recipient
  id is resolved against the server and the URL's name is never shown.
- B/F-03 — donations had no idempotency key; a timed-out retry donated twice. Client sends
  one key per intended donation; `POST /v2/wallet/donate` replays a duplicate (content-bound
  key, 24 h). PHP tests: `WalletDonateIdempotencyTest`.
- B/F-04 — confirming exchange hours pre-filled the *proposed* figure even when the other
  member had confirmed a different one; a ≥0.25 h gap sends the exchange to dispute. Now
  pre-fills the counterparty's confirmed hours, formatted for the member's locale, with a
  warning sentence.
- B/F-17 — wallet action errors shown raw; now the server's reason via `describeApiError`.
- C/F-1 — completing a group exchange moved credits on one tap; confirming did too. Both ask.
- C/F-14 — unparseable per-participant hours/weights were sent as 0 / 1; validated first.

**Journeys that could not complete**
- B/F-01 — data export never reached the member (the app discarded the streamed file). New
  GET twin of the download route; the app downloads and hands the archive to the share
  sheet. PHP tests extended in `MemberDataExportTest`.
- A/F-01 — "Sign out" on the session-restore failure screen did nothing visible; the flag is
  now cleared on sign-out and on a token-less restore.
- A/F-02 — registration that signs the member straight in was challenged by the unsaved-
  changes guard.
- C/F-2 — requesting to join a private group showed "Joined", then silently reverted. The
  server's `pending` answer is now shown as "Requested", with the organisers' message.
- C/F-4 — a 403 during offline check-in sync purged the encrypted queue including never-
  synced check-ins. The queue is kept read-only; only the confirmed purge removes it.
- B/F-08 — the exchanges list was capped at 50 with no way to see the rest; paged now.
- B/F-09 — "Exchange active" on a listing was a dead-end toast and never refreshed; it now
  opens the exchange, and the checks re-run on focus.

**Refusals reported as failures**
- B/F-05 — a blocked / vetting / safeguarding refusal on sending a message read as "try
  again"; the server's sentence is shown and the composer closes.
- B/F-06 — a hidden or blocked profile read as "Could not load — Retry"; now "not
  available" / "you cannot view" with a way back. `useApi` exposes `errorStatus`/`errorCode`.
- B/F-07 — a refused exchange transition left stale buttons; the screen re-reads on
  404/409/422.
- B/F-14 — a deleted conversation read as a load error with Retry; now "no longer available".
- C/F-11 — an ordinary member deep-linking into the event editor got "Could not load event"
  with a Retry that failed for ever; now a refusal with the way back.
- C/F-13 — sixteen bare `catch {}` blocks across the event registration, safety, credential
  and offline check-in components discarded the server's reason.
- C/F-15 — any group-exchange load error read as "not found".

**Wrong or missing information**
- C/F-6 — event detail never showed the end time or end date of a timed event.
- C/F-7 — a cancelled/postponed event never showed the organiser's reason.
- C/F-9 — two raw translation keys on the group invite screen.
- C/F-10 — editing a `joinable` federated group silently downgraded it to `listed`.
- C/F-12 — six distinct offline-scan refusals read as one generic "invalid" sentence.
- C/F-16 — the group Events tab formatted in the device zone and showed 00:00 for all-day.
- A/F-06 — the inbox "N unread" chip summed the loaded page while the badge showed the
  server total; the inbox also ignored live messages. Now the server total, and the list
  re-reads when the badge changes.
- A/F-21, C/F-5 — the events tab discarded the server's reason, and a failed *later* page
  replaced the whole list; the list is kept with an inline retry for that page.
- C/F-18 — switching a tab or filter kept the previous rows on screen until the response.
- B/F-16 — choosing an auto-translate target changed the interface language, and there was
  no language picker at all. Side effect removed; Settings → App language added (7 locales).
- B/F-10 — marking notifications read did not update the tab badge.
- B/F-11 — tapping a notification for a switched-off module pushed a second Notifications
  screen on top of the first; now a notice, no navigation.
- B/F-12 — the thread jumped to the bottom on every incoming message and lost its place when
  older messages loaded.
- B/F-15 — "Delete for everyone" was offered on other people's messages.
- B/F-20, B/F-28, B/F-29, B/F-30 — thread avatar/title from the server, message-the-other-
  party carries the name, comma-locale prefill, dead typing indicator removed.
- A/F-05 — the keyboard's Return could fire a second submit on all four auth forms.
- A/F-10 — Home fetched and rendered the feed when the feed module was off.
- A/F-12 — a reset/verify link opened while signed out was replayed after sign-in.
- A/F-14, A/F-16, A/F-18, A/F-19, A/F-20, A/F-22, A/F-15 — 40 dp icon-only buttons, password
  toggle label, offline banner on four tabs, listing save race, swipe-archive double prompt,
  auth card centring, Explore stat number formatting.
- Mechanical: Explore sections now respect the listings and feed modules; the reaction bar
  honours reduced motion; a saved resource now opens on that resource.
